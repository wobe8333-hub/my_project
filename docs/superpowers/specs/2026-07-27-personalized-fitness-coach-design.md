# 초개인화 헬스 트레이닝 서비스 — 설계 문서

## 1. 목적

키, 몸무게, 체지방률 등 개인 정보를 입력하면 AI가 운동 루틴과 식단 계획을
추천해주고, 매일 접속할 때마다 "오늘 할 일"을 보여주는 개인 맞춤형 헬스
코칭 서비스. 며칠 못 지켜도 이어서 진행할 수 있고, 궁극적으로는 초개인화된
트레이닝 경험을 제공하는 것이 목표.

- 사용자: 처음엔 본인 혼자 사용, 이후 여러 명이 사용할 수 있도록 처음부터
  로그인 기능을 갖춘다 (Supabase Auth, 이메일/비밀번호)
- 배포: Vercel에 배포

## 2. 프로필 입력 항목

| 항목 | 입력 방식 | 비고 |
|---|---|---|
| 키, 몸무게 | 직접 입력 | 기본 |
| 체지방률, 근육량 | 인바디 사진 업로드 → AI가 숫자 자동 인식 | 인식 실패 시 직접 입력으로 전환 |
| 나이, 성별 | 직접 입력 | 칼로리 계산에 필요 |
| 운동 경력 | 초보/중급/고급 선택 | 루틴 난이도 조절 |
| 주당 가능 운동 일수/시간 | 직접 입력 | 현실적인 계획을 위해 |
| 목표 | 감량/근육증가/유지 중 직접 선택, 또는 "AI가 제안" 선택 가능 | |
| 운동 환경 | 헬스장 / 홈트레이닝 선택 | |
| 보유 기구 (헬스장 선택 시) | 헬스장 이름 입력 → 실시간 웹검색으로 자동 추정 → 체크리스트로 확인/수정 | 검색이 막히면 수동 체크리스트로 전환 |
| 음식 알레르기/선호도 | 직접 입력 (텍스트 태그) | 식단 추천에서 자동 제외 |

## 3. 헬스장 기구 실시간 조회

- 사용자가 입력한 헬스장 이름으로 검색엔진 결과 페이지를 서버가 직접 열어서
  관련 정보(공식 홈페이지, 블로그 후기 등)를 수집
- 수집된 텍스트를 AI에게 보내 "이 헬스장에 있을 것으로 보이는 기구 목록"을
  추출
- 결과를 체크리스트로 화면에 보여주고 사용자가 직접 확인/수정 가능
- **알려진 리스크**: 검색엔진이 자동 접근을 감지해 차단(캡차 등)할 수 있음.
  이 경우 자동 조회를 건너뛰고 빈 체크리스트를 보여줘 사용자가 직접
  선택하도록 한다 (서비스 전체가 멈추지 않게 처리).

## 4. AI 계획 생성 (주 단위 생성 + 재생성)

- 프로필이 완성되면 AI(OpenRouter)가 **1주일치** 운동 루틴 + 식단 계획을
  한 번에 생성해서 저장
- 한 주가 끝나면, 그 주의 실제 완료 기록(얼마나 지켰는지)을 반영해 다음
  1주일치 계획을 새로 생성
- **재시작 규칙**: 마지막 완료 기록으로부터 **3일 이상** 접속하지 않고
  돌아온 경우, 기존 계획을 이어가지 않고 그날 상태 기준으로 계획을 새로
  생성한다.

## 5. "이어서 진행" 로직 (핵심 요구사항)

- 진행은 달력 날짜가 아니라 **진행 순번(day pointer)**으로 관리한다.
- 사용자가 "오늘 완료"를 누르면 순번이 하나 증가한다. 며칠 접속하지 않아도
  순번은 그대로 유지되며, 밀린 날들을 몰아서 시키지 않는다.
- 단, 위 4번 규칙에 따라 3일 이상 공백이 생기면 순번을 유지한 채로 그
  시점 계획만 새로 생성한다 (몸무게 등 변경 여부와 무관하게 최신 프로필
  기준으로 재생성).

## 6. 화면 구성

1. 회원가입/로그인
2. 프로필 입력/수정 (인바디 사진 업로드, 기구 체크리스트 포함)
3. 오늘의 할 일 — 오늘의 운동 + 오늘의 식단, "완료" 체크 버튼
4. 진행 기록/통계 — 지금까지의 완료율, 주차별 계획 히스토리

## 7. 데이터 저장 (Supabase)

- `profiles`: 사용자별 신체정보, 목표, 환경, 알레르기 등 (auth.users와 연결, RLS로 본인 데이터만 접근)
- `gym_equipment`: 사용자별 보유 기구 체크리스트
- `weekly_plans`: 주차별 생성된 계획 (운동+식단, JSON)
- `daily_progress`: 일자별 완료 여부, 진행 순번(day pointer)

## 8. AI 활용 (OpenRouter)

- 텍스트 분석: 헬스장 기구 추정, 주간 루틴/식단 생성
- 비전(이미지 인식): 인바디 사진에서 체지방률/근육량 숫자 추출
- 사용 모델은 환경변수로 설정 가능하게 구성 (텍스트용/비전용 각각 지정)

## 9. 보안

- Supabase Auth로 계정 관리, RLS로 사용자별 데이터 완전 분리
- OpenRouter API 키 등 모든 민감 값은 `.env`에 저장, 코드에 하드코딩하지 않음
- 인바디 사진 등 개인 신체정보는 본인만 접근 가능하도록 저장소 접근 제한
- 실 개인정보를 예시/테스트 데이터로 사용하지 않음 (CLAUDE.md 보안 규칙 준수)
- 배포 전 비밀 키·개인정보 유출 여부 점검

## 10. 필요한 사전 준비물 (사용자 본인이 발급)

- OpenRouter 계정 + API 키 (openrouter.ai, 사용량 기반 소액 과금)

## 11. 테스트 & 배포

- 구현 중간중간 실제로 프로필 입력 → 계획 생성 → 완료 체크가 잘 되는지
  직접 테스트하며 진행
- 완성 후 Vercel로 배포, 접속 주소 안내

## 12. 범위 제외 (이번 버전에서 하지 않는 것)

- 이메일/푸시 알림 (접속 시 대시보드로만 확인)
- 평소 활동량, 부상/건강 주의사항 입력 (요청에 따라 이번 범위에서 제외)
- 헬스장 프랜차이즈 사전 등록 데이터베이스 (실시간 검색 방식으로 대체)
